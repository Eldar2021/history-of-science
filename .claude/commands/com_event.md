Draft one or more timeline events for Uchkun following the content contract. Arguments: $ARGUMENTS (event names or years; if empty, take the next events from `backend/content/top100.json` — the lowest `rank` whose slug has no row in `events` yet).

1. Read `doc/icerik.md` in full: eras, disciplines, the event template, the body tools table, and the writing rules (voice, no formulas in the narrative, one analogy plus where it breaks, honesty about uncertainty, no lone-hero narrative, Central Asia emphasis, women and non-Western contributions visible).
2. Research with web search: at least 2 independent sources, one an encyclopedia (Britannica, Stanford Encyclopedia of Philosophy, English Wikipedia, MacTutor, university pages). Note any disagreement on the year and set `precision` accordingly (`exact` / `circa` / `decade` / `century`). Say in the body when a well-known anecdote rests on one late account rather than staging it as fact.
3. Find images on Wikimedia Commons and **read the licence from the Commons API**, never assert it. A figure without an `Author · Licence · URL` caption does not go in the body. Add a video only if the channel can be verified (oEmbed) and the video is genuinely good.
4. Write the event in **all four languages** (en, ru, ky, tr). English is the source; Kyrgyz is written with the Turkish and Russian versions in view (`doc/i18n.md`) and marked `status: "machine"`.
   - **There is no word ceiling on the body.** Length follows the material: importance 5 goes deep, importance 3 stops early. Every paragraph must bring a new fact; a paragraph that restates the one before it gets cut.
   - The summary is capped at **200 characters** — that is a layout constraint (timeline card, OG image), not a style one.
5. Output one JSON file per event at `backend/content/drafts/<slug>.json` in the contract shape: `slug, year, year_end, precision, importance, status: "review", drafted_by: "ai", source_locale, place_precision, lat, lng, image{path,credit,license,source_url}, disciplines[], people[{slug,birth_year,death_year,role,name{en,ru,ky,tr}}], builds_on[], sources[{title,url,kind}], research_note, translations{en,ru,ky,tr}{title,summary,body,why_it_matters,if_you_were_there,place_name,status}`.
   - `research_note` records what was confirmed, what is flagged in the body, and what the reviewer should check.
   - `builds_on` may name events that do not exist yet; the loader inserts a link only when both ends exist.
6. Validate and load: `node backend/scripts/draft-to-sql.mjs backend/content/drafts/<slug>.json` and pipe it to the database. The script enforces the contract and refuses to touch a published event. **Never write `published`** — that is the user's action in the admin (ADR-014).
7. Finish with a 2-3 line note in Turkish listing what the user should verify: an uncertain year, a competing priority claim, anything a second source could not confirm.
